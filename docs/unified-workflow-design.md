# 统一任务与阶段协作设计

## 目标与范围

普通用户只提交任务描述及精确授权范围，不选择本地演示、Pi 或端口扫描类型。Planner 在启动后先生成受约束计划，Scheduler 保留能力匹配、预算、依赖和租约职责，Worker 通过共享结果与只读复核完成阶段协作。

本次为已确认的跨层工作流功能升级；原有纯 Web UI 重构不改后端的约定继续有效。保留旧显式任务和本地演示 API，不新增数据库表，不升级基础依赖。

## 设计模式与性能预检

- 模式：沿用执行器策略、集中编排和事务事件通知；用小型显式状态机管理规划及阶段，不引入通用工作流框架、投票框架或多层类体系。
- 数据结构：以 goal/task/target 为键的 Map 聚合状态，依赖使用邻接关系；目标为一次阶段验收 O(T+F+E+D)，避免阶段×任务的重复遍历及全连接依赖。
- 规模：遵守当前任务总量 1000、并发上限 64、授权端口 16 的预算。模型、证据读取和网络不进入 Run 行锁事务，快照保持有界，超过覆盖能力必须明确失败而非误判通过。
- 验证：Go vet/build、Pi TypeScript 检查、前端 lint/type-check/build，以及隔离 PostgreSQL + 本地工具目标 + 本地协议提供方的跨层行为检查和真实浏览器验收。离线协议提供方不代表真实模型能力已验证。

## 方案取舍

| 方案 | 适配度 | 复杂度 | 可维护性 | 结论 |
| --- | --- | --- | --- | --- |
| 只合并 UI，继续由前端生成任务 | 高 | 低 | 低 | 不能满足 Planner 规划和阶段验收，不采用 |
| 复用 Goal/Task/Blackboard、Pi 与现有调度器 | 高 | 中 | 高 | 推荐；只补领域契约、规划与阶段门禁 |
| 新建阶段表并引入通用工作流/多 Agent 框架 | 中 | 高 | 中 | 没有迁移和运维必要，不采用 |

评分是针对本项目的定性判断，不是性能基准。仅第二种方案进入实施。

## 数据流与边界

1. `POST /runs` 接收 objective、scope、预算及 deadline；新目标驱动入口不接受混合手工任务图。
2. 启动进入 planning，由配置好的 Pi 模型生成结构化阶段与任务；规划工具不具备探测权限。
3. Go 对计划的目标、工具、端口、任务类别、事实类别、阶段和任务 DAG、预算进行验证；模型输出视为不可信数据。
4. 规划在事务外执行，落库重新检查运行状态与代际；取消和迟到规划结果不能重新激活 Run。
5. Scheduler 只分配准入阶段任务；Worker 的结果、事实、证据及提案按现有租约机制提交。
6. 只读复核任务读取阶段产出，不重复扫描。优先由其他 Worker 执行，单 Worker 明确标记自检。
7. 服务端核验复核结论与当前输入版本后推进阶段；执行 completed 不等于阶段 achieved。
8. 后续阶段只在前置阶段验收通过后运行。修复与重试有界；预算不足、缺证据或不可恢复失败必须有可解释终态。

## 契约方向

- RunSpec 新增 objective；旧 goals/tasks 兼容，新入口由服务端生成。
- Plan 包含 summary、goals、tasks；实际 usage 由 Go 统计，模型不能自行声明。未知价格保持 cost_known=false。
- GoalSpec 保留 required_facts，增加 depends_on 与 targets。Goal.SuccessCriteria、Run.Config 和 Task.Input 保存规划及阶段元数据。
- RunResult 增加 stages 快照，包含阶段状态、工作进度、验收条件、复核者、self_review/cross_review 和原因。
- 新状态规划及阶段事件仅反映持久化事实，不生成前端模拟轨迹。

## 创建交互

- 用户只填写任务目标与目标资产：同一输入区域接受 1–10 条精确 HTTP(S) URL，或单一裸 IPv4；不接受混合范围，不要求填写端口或选择工具。
- 前端原样提交裸 IPv4，省略 tools/tcp_ports。服务端规范化候选能力：精确 URL 可使用 http.observe，单一裸 IPv4 可由 Planner 选择 http.observe、tcp.discover 或两者分阶段执行；目标资产始终不扩大。
- Planner 根据 objective 选择步骤与具体端口，不使用本地关键词规则或默认端口清单替代模型规划。ResolvePlanScope 以纯函数校验实际任务，收敛执行工具和端口，并与计划同事务固定 Run.Scope 与 config.Scope；Worker 只使用已固定范围。
- 显式 API 工具/端口限制继续作为上限。省略端口不等于取消执行限制：模型选定的 TCP 端口并集仍须合法、唯一且不超过当前执行器预算；执行阶段保留严格范围校验。
- 不预填公网目标。保留范围绑定的授权确认、抽屉草稿、异步失败和重复提交保护。
- 并发、任务预算、截止时间和可选名称放高级设置。
- 模型未配置时明确拒绝真实任务，不自动回退模拟执行。

## UI 与兼容

保留 Planner → Scheduler → Worker → 当前任务 → Blackboard 的全宽纵向协作舞台、可读执行者名称和单一真实事件交接。阶段摘要以服务端 snapshot 为准；事件动画不是状态源。新阶段字段可选，旧运行无需伪造阶段。继续支持取消、刷新、切换运行和暂停视图后的状态恢复。
